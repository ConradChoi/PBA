# Multi-language (i18n) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve every public page in Korean, English, Simplified Chinese, Traditional Chinese and Japanese, picked per visitor from their browser (then country, then Korean), without changing a single URL.

**Architecture:** `next-intl` in its "without i18n routing" mode: a request-scoped config resolves the locale from cookie → `Accept-Language` → `CloudFront-Viewer-Country` → `ko`, then loads that locale's messages. Public pages move into a `(site)` route group with their own root layout (`<html lang>` per visitor), while `/admin` gets its own root layout that stays Korean. Korean copy moves out of components and content files into `messages/ko.ts`, whose shape becomes the `Messages` type every other locale must satisfy — so a missing translation fails the build.

**Tech Stack:** Next.js 15 App Router, next-intl 4, TypeScript, Vitest, Supabase.

**Spec:** `docs/superpowers/specs/2026-09-19-i18n-design.md`

## Global Constraints

- **Five locales:** `ko` (default), `en`, `zh-CN`, `zh-TW`, `ja`. Korean is what any unrecognized visitor gets.
- **No URL changes.** No locale segment, no next-intl middleware, no redirect. The existing `middleware.ts` (admin session) is untouched.
- **Locale decision order:** `NEXT_LOCALE` cookie → `Accept-Language` (q-ordered) → `CloudFront-Viewer-Country` header → `ko`.
- **Completeness is enforced by types:** `ko.ts` is the source of truth and exports `type Messages = typeof ko`; every other locale file ends with `satisfies Messages`.
- **Stored codes never translate:** layer ids, `architecture_level` values, business-stage/team-size/band codes. Layer display names (VALUE, CUSTOMER, OFFER, EXPERIENCE, PROCESS, DATA & INTELLIGENCE, SCALE) stay English in every locale — they are PBA method terms.
- **Admin stays Korean** (`<html lang="ko">`), including the result preview popup, which passes `locale="ko"` explicitly.
- **Company info:** Korean block on `ko`; the English block (YLIA Co., Ltd. / Choi Jong Hoon / 4F, 362 Ori-ro, Gwangmyeong-si, Gyeonggi-do, Republic of Korea / Business Registration No. 832-86-03446) on every other locale. Footer copyright reads `© 2026 YLIA Co., Ltd. All rights reserved.` in all locales.
- **Privacy policy translations** carry a line at the top: the translation is for convenience and the Korean version prevails. Effective date stays 2026년 9월 20일 in every locale.
- **Operator-written content is never translated:** notice bodies, consult messages, business-stage "기타" free text show exactly as entered.
- `Vary: Accept-Language, Cookie, CloudFront-Viewer-Country` on public responses, so CloudFront can't serve one visitor's language to another.
- The existing suite (197 tests) must stay green; run `npm test` before each commit.

- [ ] **Step 4: Implement `src/i18n/locales.ts`**

```ts
export const LOCALES = ["ko", "en", "zh-CN", "zh-TW", "ja"] as const;

export type Locale = (typeof LOCALES)[number];

export const DEFAULT_LOCALE: Locale = "ko";

// Shown in the switcher in each language's own name, so a visitor who can't
// read the current language can still find theirs.
export const LOCALE_LABELS: Record<Locale, string> = {
  ko: "한국어",
  en: "English",
  "zh-CN": "简体中文",
  "zh-TW": "繁體中文",
  ja: "日本語",
};

const COUNTRY_LOCALE: Record<string, Locale> = {
  KR: "ko",
  JP: "ja",
  CN: "zh-CN",
  SG: "zh-CN",
  TW: "zh-TW",
  HK: "zh-TW",
  MO: "zh-TW",
};

function isLocale(value: string | null | undefined): value is Locale {
  return LOCALES.includes(value as Locale);
}

function matchLanguageTag(tag: string): Locale | null {
  const lower = tag.toLowerCase();

  if (lower.startsWith("zh")) {
    // Script subtag wins; otherwise the region decides. Bare "zh" is
    // Simplified, which is what mainland and Singapore browsers send.
    if (lower.includes("hant") || /\b(tw|hk|mo)\b/.test(lower)) {
      return "zh-TW";
    }
    return "zh-CN";
  }

  const primary = lower.split("-")[0];
  return isLocale(primary) ? primary : null;
}

export function resolveLocale({
  cookie,
  acceptLanguage,
  country,
}: {
  cookie: string | null;
  acceptLanguage: string | null;
  country: string | null;
}): Locale {
  // 1. What the visitor chose in the switcher.
  if (isLocale(cookie)) {
    return cookie;
  }

  // 2. What their browser asks for, in q order.
  if (acceptLanguage) {
    const tags = acceptLanguage
      .split(",")
      .map((part) => {
        const [tag, ...params] = part.trim().split(";");
        const q = params
          .map((param) => param.trim())
          .find((param) => param.startsWith("q="));
        return { tag, q: q ? Number(q.slice(2)) : 1 };
      })
      .filter((entry) => entry.tag.length > 0)
      .sort((a, b) => b.q - a.q);

    for (const { tag } of tags) {
      const match = matchLanguageTag(tag);
      if (match) {
        return match;
      }
    }
  }

  // 3. Where they are, if CloudFront told us.
  if (country) {
    return COUNTRY_LOCALE[country.toUpperCase()] ?? "en";
  }

  // 4. Nothing to go on — including search crawlers, which keeps Korean
  //    indexed.
  return DEFAULT_LOCALE;
}
```

- [ ] **Step 7: Create `src/i18n/request.ts`**

```ts
import { getRequestConfig } from "next-intl/server";
import { cookies, headers } from "next/headers";
import { resolveLocale } from "./locales";

export default getRequestConfig(async () => {
  const [cookieStore, headerStore] = await Promise.all([cookies(), headers()]);
  const locale = resolveLocale({
    cookie: cookieStore.get("NEXT_LOCALE")?.value ?? null,
    acceptLanguage: headerStore.get("accept-language"),
    // Amplify sits behind CloudFront; the header is absent if it isn't
    // forwarded, and the browser language alone still decides.
    country: headerStore.get("cloudfront-viewer-country"),
  });

  return {
    locale,
    messages: (await import(`./messages/${locale}.ts`)).default,
  };
});
```

          <NoticeBanner />
          <div className="flex flex-1 flex-col">{children}</div>
          <SiteFooter />
        </NextIntlClientProvider>
      </body>

- [ ] **Step 1: Create the shared dropdown**

`src/components/ui/Dropdown.tsx` is a client component: a trigger button plus a panel that opens anchored directly under it (`absolute right-0 top-full mt-1`), inside a `relative` wrapper so it never moves elsewhere; white card, border, shadow, rounded, `min-w-max`, `z-40`. It closes on outside click (a `mousedown` listener on `document`) and on Escape, supports ArrowUp/ArrowDown to move focus between items and Enter to pick, and sets `aria-haspopup="listbox"` / `aria-expanded` on the trigger with `role="listbox"`/`role="option"` on the panel. Props: `label` (trigger content), `ariaLabel`, and `items: { key: string; label: string; selected: boolean; onSelect: () => void }[]`.

- [ ] **Step 2: Create `src/components/site/LocaleSwitcher.tsx`**

```tsx
"use client";

import { useRouter } from "next/navigation";
import { Dropdown } from "@/components/ui/Dropdown";
import { LOCALES, LOCALE_LABELS, type Locale } from "@/i18n/locales";

export function LocaleSwitcher({ locale, ariaLabel }: { locale: Locale; ariaLabel: string }) {
  const router = useRouter();

  function choose(next: Locale) {
    // A year is long enough that a returning visitor keeps their choice, and
    // the cookie is the first thing resolveLocale looks at.
    document.cookie = `NEXT_LOCALE=${next}; path=/; max-age=31536000; samesite=lax`;
    router.refresh();
  }

  return (
    <Dropdown
      ariaLabel={ariaLabel}
      label={`🌐 ${LOCALE_LABELS[locale]}`}
      items={LOCALES.map((value) => ({
        key: value,
        label: LOCALE_LABELS[value],
        selected: value === locale,
        onSelect: () => choose(value),
      }))}
    />
  );
}
```

- [ ] **Step 3: Put it in the header**

`SiteHeader` renders the brand on the left and `<LocaleSwitcher locale={await getLocale()} ariaLabel={t("languageLabel")} />` on the right, with `print:hidden` on the switcher.
