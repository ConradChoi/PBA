# 결과 보강 콘텐츠 초안 (검토용)

- 작성: Claude 초안, 2026-09-19
- 설계: `docs/superpowers/specs/2026-09-19-result-enrichment-design.md`
- 검토 방법: 이 문서에서 문구를 직접 고치거나 메모를 달아 주세요. 확정된 문구는 `src/lib/content/`의 데이터 파일로 옮깁니다. 구현은 이 초안으로 먼저 진행합니다.
- 원칙: 무료 결과는 "무엇이 문제인가"까지 보여 줍니다. "왜 그런가"는 가설 1개만 맛보기로 보여 주고, 검증과 해결은 상담 영역으로 남깁니다. "검증된 방법론" 같은 표현은 쓰지 않습니다.

---

## 1. 성숙도 Level 이름

응답 척도(1~5)와 같은 의미를 갖습니다. Level은 레이어 4문항 평균을 반올림한 값입니다(합계 4–5 → L1, 6–9 → L2, 10–13 → L3, 14–17 → L4, 18–20 → L5).

| Level | 이름 | 응답 척도 의미 |
|---|---|---|
| L1 | 미정의 | 전혀 정리되지 않음 |
| L2 | 인식 | 생각은 있으나 구체적이지 않음 |
| L3 | 정리 | 어느 정도 정리되어 있음 |
| L4 | 운영 | 실제 운영에 적용되고 있음 |
| L5 | 체계화 | 명확하게 정의되고 데이터로 관리됨 |

---

## 2. 레이어별 성숙도 앵커 (35줄)

결과 화면에서 각 레이어의 현재 Level에 해당하는 한 줄만 보입니다.

### VALUE
| Level | 앵커 |
|---|---|
| L1 | 고객이 해결하려는 문제와 우리가 주는 가치가 아직 정리되지 않은 상태입니다. |
| L2 | 해결하려는 문제는 떠올릴 수 있지만, 한 문장으로 정의하거나 기존 대안과 비교해 설명하지는 못하는 상태입니다. |
| L3 | 핵심 문제와 차별점은 정리되어 있지만, 실제 고객이 원하는 가치와 일치하는지는 확인되지 않았습니다. |
| L4 | 정리된 가치 제안이 영업·마케팅에 실제로 쓰이고, 고객이 비용을 지불하는 이유를 설명할 수 있습니다. |
| L5 | 가치 제안이 고객 인터뷰와 구매·이탈 데이터로 확인되고 주기적으로 갱신됩니다. |

### CUSTOMER
| Level | 앵커 |
|---|---|
| L1 | 누가 우리 고객인지 구체적으로 정의되어 있지 않습니다. |
| L2 | 대략적인 고객층은 있지만, 사용자와 구매자, 고객별 니즈를 구분하지 않습니다. |
| L3 | 핵심 고객과 구매자·사용자는 정의되어 있지만, 구매를 결정하게 만드는 계기는 추정 수준입니다. |
| L4 | 고객 정의와 구매 계기가 마케팅·영업 대상을 정하는 데 실제로 쓰이고 있습니다. |
| L5 | 고객군별 전환·유지 데이터로 고객 정의를 확인하고 갱신합니다. |

### OFFER
| Level | 앵커 |
|---|---|
| L1 | 무엇을 얼마에 파는지가 고객이나 상황마다 달라지는 상태입니다. |
| L2 | 핵심 상품은 있지만, 가격 기준과 다음 상품으로 이어지는 구조가 없습니다. |
| L3 | 핵심 상품과 가격 기준은 정리되어 있지만, 입문→핵심→고가로 이어지는 구조와 반복 매출은 아직 설계 단계입니다. |
| L4 | 상품 사다리와 가격 체계가 실제 판매에 적용되고, 반복 매출이 일부 발생합니다. |
| L5 | 상품별 전환율·객단가·재구매 데이터로 상품 구성과 가격을 조정합니다. |

### EXPERIENCE
| Level | 앵커 |
|---|---|
| L1 | 고객이 어떻게 우리를 알게 되고 어디서 떠나는지 파악되지 않았습니다. |
| L2 | 주요 유입 경로는 짐작하지만, 구매 이후의 여정과 이탈 지점은 관리하지 않습니다. |
| L3 | 관심부터 재구매까지의 여정은 그려져 있지만, 경험의 질이 담당자에 따라 달라집니다. |
| L4 | 설계된 고객 여정이 실제로 운영되고, 주요 이탈 지점을 파악해 대응합니다. |
| L5 | 여정 단계별 전환·이탈 데이터를 추적하며 경험을 계속 개선합니다. |

### PROCESS
| Level | 앵커 |
|---|---|
| L1 | 업무가 정해진 흐름 없이 그때그때 사람의 판단으로 처리됩니다. |
| L2 | 업무 흐름은 머릿속에 있지만 문서로 정리되지 않았고, 반복 수작업이 많습니다. |
| L3 | 주요 프로세스는 정리되어 있지만, 사람과 시스템의 역할은 일부만 나뉘어 있습니다. |
| L4 | 정의된 프로세스대로 업무가 돌아가며, 대표나 특정 직원이 빠져도 대부분 처리됩니다. |
| L5 | 프로세스 성과를 측정하고, 반복 업무를 자동화하며 계속 개선합니다. |

### DATA & INTELLIGENCE
| Level | 앵커 |
|---|---|
| L1 | 고객 행동이나 서비스 이용 데이터가 거의 기록되지 않습니다. |
| L2 | 일부 데이터는 쌓이지만, 무엇을 왜 수집하는지 정의되어 있지 않습니다. |
| L3 | 수집할 데이터와 목적은 정의되어 있지만, 의사결정에는 가끔만 쓰입니다. |
| L4 | 데이터를 근거로 고객 경험이나 업무를 실제로 개선하고 있습니다. |
| L5 | 데이터가 의사결정의 기본이며, AI·자동화 적용 지점이 구체적으로 운영됩니다. |

### SCALE
| Level | 앵커 |
|---|---|
| L1 | 매출이 늘면 대표의 업무시간도 그만큼 늘어나는 구조입니다. |
| L2 | 확장이 필요하다고 느끼지만, 업무 표준이나 매뉴얼이 없습니다. |
| L3 | 일부 업무는 표준화되어 있지만, 다른 사람이 같은 품질을 내기는 아직 어렵습니다. |
| L4 | 표준과 매뉴얼로 다른 사람도 같은 품질을 내며, 반복 매출 구조가 작동합니다. |
| L5 | 매출이 늘어도 운영 부담이 비례해 늘지 않고, 구독·라이선스·파트너 구조로 확장합니다. |

## 3. 위험 신호 규칙 (5개)

조건을 모두 만족하면 해당됩니다. 한 사람에게 우선순위가 높은 순으로 최대 2개만 보입니다.

| 우선순위 | 제목 | 조건 | 설명 |
|---|---|---|---|
| 1 | 대표 의존 병목 | PROCESS ≤ L2 그리고 SCALE ≤ L2 | 업무가 대표에게 묶여 있어, 성장이 대표의 시간에 막힐 가능성이 큽니다. |
| 2 | 구조 없는 확장 | VALUE ≤ L2 그리고 SCALE ≥ L4 | 가치 정의가 흐린 상태에서 규모를 키우고 있습니다. 확장할수록 고객 이탈과 가격 압박이 커질 수 있습니다. |
| 3 | 정리 전 자동화 | DATA ≥ L4 그리고 PROCESS ≤ L2 | 데이터·AI 활용에 비해 업무 흐름이 정리되어 있지 않습니다. 정리되지 않은 프로세스를 자동화하면 비효율도 함께 자동화됩니다. |
| 4 | 고객 없는 상품 설계 | CUSTOMER ≤ L2 그리고 OFFER ≥ L4 | 상품 구조는 갖춰졌지만 핵심 고객 정의가 약합니다. 상품이 고객이 아니라 공급자 관점에서 설계되었을 수 있습니다. |
| 5 | 보이지 않는 이탈 | EXPERIENCE ≤ L2 그리고 DATA ≤ L2 | 고객이 어디서, 왜 떠나는지 보이지 않는 상태입니다. 개선이 감에 의존하게 됩니다. |

## 4. 원인 가설 (레이어당 2개)

- **공개용:** 결과 화면에서 가장 낮은 레이어 1개에 대해서만 보입니다.
- **상담용:** 어드민 결과 팝업에서만 보입니다. 상담에서 확인할 두 번째 가설과 확인 포인트예요.

| 레이어 | 공개용 가설 | 상담용 가설 (내부) |
|---|---|---|
| VALUE | 고객 인터뷰 없이 공급자 관점에서 가치를 정의했을 가능성이 있습니다. | 여러 고객군의 요구를 하나의 가치 제안에 담으려다 메시지가 흐려졌을 가능성. CUSTOMER 정의와 함께 확인. |
| CUSTOMER | '누구나 고객'이라는 넓은 정의로 시작해, 핵심 고객을 좁히지 못했을 가능성이 있습니다. | 구매자와 사용자가 다른데 사용자만 보고 설계했을 가능성. B2B·교육·헬스케어에서 흔함. 실제 결제 결정자를 확인. |
| OFFER | 고객 요청마다 맞춤으로 대응하다 상품이 표준화되지 않았을 가능성이 있습니다. | 가격을 원가나 경쟁사 기준으로 정해, 고객이 체감하는 가치와 연결되지 않았을 가능성. 가격 결정 근거를 확인. |
| EXPERIENCE | 유입과 첫 구매에 집중하느라 구매 이후의 경험이 설계되지 않았을 가능성이 있습니다. | 고객 응대가 특정 담당자 역량에 의존해 담당자마다 경험 품질이 달라질 가능성. 응대 기록과 담당자별 재구매율을 확인. |
| PROCESS | 대표가 대부분의 판단을 직접 하면서, 업무 흐름을 문서로 만들 기회가 없었을 가능성이 있습니다. | 프로세스 정의 없이 도구를 먼저 도입해 업무가 도구마다 흩어졌을 가능성. 사용 중인 도구 목록과 업무 연결을 확인. |
| DATA | 데이터를 '나중에 볼 것'으로 미뤄, 무엇을 왜 기록할지 정하지 않았을 가능성이 있습니다. | 데이터는 쌓이지만 여러 도구에 흩어져 한곳에서 볼 수 없을 가능성. 데이터 위치와 담당자를 확인. |
| SCALE | '대표가 직접 해야 품질이 나온다'는 전제로 운영해, 표준화가 계속 미뤄졌을 가능성이 있습니다. | 반복 매출 없이 프로젝트성 매출에 의존해, 매출이 투입 인력에 비례할 가능성. 매출 구성을 확인. |

## 5. 새 화면 문구

| 위치 | 문구 |
|---|---|
| 성숙도 섹션 제목 | 레이어별 성숙도 |
| 위험 신호 섹션 제목 | 위험 신호 |
| 가설 카드 제목 | 가능성 높은 원인 가설 |
| 가설 카드 본문 앞 | {레이어}가 낮은 원인으로 가장 흔한 경우는 다음과 같습니다. |
| 가설 카드 아래 안내 | 위 가설이 실제 원인인지, 상담에서 프로세스와 데이터를 함께 확인해 드립니다. |
| 상담 버튼 | 원인 가설 검증 상담받기 |
| 공감도 질문 | 이 진단 결과가 실제 상황과 맞나요? |
| 공감도 척도 양끝 | 1 전혀 다르다 · 5 매우 정확하다 |
| 공감도 저장 후 | 의견 감사합니다. 다음 진단을 개선하는 데 쓰입니다. |
| 성과 카드 제목 (접힘) | 더 정확한 분석을 위해 알려주세요 (선택) |
| 성과 카드 안내 | 선택 입력이며 입력하지 않아도 불이익은 없습니다. 진단 정확도 향상과 통계에 쓰이며, 개인정보에 동의하신 경우 이름·이메일과 함께 보관되다가 1년 후 식별 정보가 삭제됩니다. |
| 성과 항목 | 연 매출 / 최근 12개월 매출 변화 (인원은 기본 정보의 팀 규모 칩으로 받음) |
| 성과 제출 버튼 · 완료 | 안내를 확인했으며 제출합니다 · 알려주셔서 감사합니다. |
